 This is a classic Go Win32 dilemma.
 Under the hood in golang.org/x/sys/windows:
    Handle is an alias for uintptr.
    HWND is an alias for Handle.
 At runtime, they are identical. However, the x/sys/windows library itself is incredibly inconsistent. Some of its own native structs use Handle, and some use HWND.
 The Recommendation: Standardize entirely on windows.Handle across your codebase.
 If you try to strictly use HWND for windows and Handle for Mutexes/DCs/Processes, you will end up fighting Go's strong typing. You'll constantly be doing windows.HWND(myHandle) or windows.Handle(myHwnd) just to pass variables into basic functions like SetWindowPos, because Go does not allow implicit conversion between defined types, even if their underlying types are identical."
